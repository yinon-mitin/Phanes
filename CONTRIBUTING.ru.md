# Участие в разработке

[English](CONTRIBUTING.md) · [Русский](CONTRIBUTING.ru.md)

Изменения должны быть небольшими, проверяемыми и не содержать рабочих данных.

## Процесс

1. Создайте ветку от `main`.
2. Измените контракт Compose, документацию или автоматизацию.
3. Выполните `make test ENV_FILE=stack/.env.example`.
4. При обновлении образов запустите `make update-lock` и проверьте каждый digest.
5. Откройте pull request с описанием миграции и отката.

## Правила

- Не добавляйте `.env`, `appdata`, названия медиа, торрент-состояние, API-ключи, токены, базы, логи и backup-архивы.
- Не заменяйте immutable digest плавающими тегами.
- Документируйте новые порты, mounts, границы состояния и требования к восстановлению.
- Считайте миграции баз необратимыми, пока восстановление не проверено.
- Закрепляйте GitHub Actions по commit SHA.

Изменение готово, когда статические проверки прошли, diff просмотрен, а для изменений runtime существует понятный откат.
